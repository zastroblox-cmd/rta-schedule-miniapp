# Owner Mode — подготовка к внедрению

Статус: **изолированный прототип подготовлен; в опубликованное приложение не внедрён**.

## Что есть в этой ветке

- `owner-mode-preview.html` — автономный интерактивный прототип панели Owner Lounge.
- Панели: System Scanner, Personal Studio, Creator Stats, Secret Lab, Activity Universe.
- Настройки темы, свечения, анимаций и стеклянных карточек; предпросмотр эффектов; переключение разделов и узлов карты.
- В интерфейсе явно указано, что проверка работает на демонстрационном объекте, а не на настоящем расписании.
- Основной `index.html`, JSON расписаний и адаптеры не изменены.

## Принятые требования

1. Главная и профиль получают компактную корону и подпись «Создатель приложения» / «Владелец проекта».
2. Скрытый вход в Owner Mode виден только подтверждённому владельцу.
3. Все эффекты и инструменты доступны сразу; XP и достижения — только статистика, не система блокировок.
4. Дизайн обычного расписания и пользовательские сценарии не меняются.
5. Настройки меняются внутри приложения и сохраняются между запусками.
6. Никаких вымышленных показателей: статистика строится из реальных событий.

## Обязательные шаги перед production

GitHub Pages — статический хостинг. Нельзя безопасно спрятать секретный доступ только CSS/JavaScript или жёстко зашитым Telegram ID: код виден всем посетителям. Перед внедрением необходимо выбрать/поднять backend и базу данных.

### Серверный контракт

- `POST /api/owner/session`: принять Telegram Web App initData, проверить подпись на сервере и срок давности, извлечь Telegram user ID; вернуть короткоживущую сессию только если ID есть в серверном allowlist владельцев.
- Все `/api/owner/*` endpoints требуют проверенную сессию. Не принимать роль владельца из клиентского JSON.
- `GET /api/owner/diagnostics`: проверить опубликованные файлы расписаний, схему JSON, обязательные поля, неизвестные группы, пересечения времени, исключения/даты и состояние API.
- `GET/PUT /api/owner/preferences`: читать и сохранять темы/эффекты на сервере с привязкой к owner ID; локальное хранилище использовать только как быстрый кэш.
- `GET /api/owner/activity`: отдавать журнал реальных событий. Записывать запуск диагностики, результат, обновление расписания и автора изменения.
- Секретные эффекты могут запускаться на клиенте, но endpoint управления/статистики всё равно защищать.
- Rate limiting, безопасные заголовки, валидация входных данных, журнал ошибок, резервное копирование базы.

### Настройки, которые нужны в серверном окружении

- `TELEGRAM_BOT_TOKEN` — только на сервере, никогда не в публичном JS.
- `OWNER_TELEGRAM_IDS` — список разрешённых числовых Telegram ID, только на сервере.
- `DATABASE_URL` — секрет подключения к БД.
- `APP_ORIGIN` — разрешённый origin Mini App.

## Чек-лист проверки перед командой внедрения

- [ ] Выбран backend/хостинг и база.
- [ ] Серверная проверка Telegram initData проходит тесты; подмена user ID не даёт доступ.
- [ ] Обычный аккаунт не видит корону и не может вызвать owner API.
- [ ] Владелец видит корону на главной и отметку в профиле.
- [ ] Все пять модулей работают на реальных данных либо явно показывают, что источник недоступен.
- [ ] Настройки переживают перезапуск и синхронизируются между устройствами.
- [ ] Диагностика не изменяет расписание.
- [ ] Тестированы Android Telegram, desktop Telegram и обычный браузер.
- [ ] Изменения выпускаются отдельным проверяемым коммитом/PR; только после подтверждения пользователя — в main.

## Как открыть прототип

Открой `owner-mode-preview.html` локально в браузере или через preview в редакторе. Он изолирован от рабочего приложения и не подключается к реальному Telegram-профилю, расписанию, API или БД.
