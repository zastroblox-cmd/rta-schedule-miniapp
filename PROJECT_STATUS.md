## 4 курс — подключение 21.10.2026
Источник: `ЮФ 4 к офо с 05.10(7).pdf`, актуализированное расписание на осенний семестр 2026/2027.
- `data/course4-schedule.json`: 73 записи по пяти группам, включая даты занятий, исключения, преподавателей, аудитории и явные маркеры чётной/нечётной недели.
- `data/course4-adapter.js`: календарный резолвер; ограничивает занятия осенним семестром 2026 года, соблюдает точные даты/исключения и приоритет курсового часа.
- `index.html`: 4 курс добавлен в выбор курса/группы и маршрутизацию расписания; другие курсы используют прежние ветки.
- Программная проверка календаря 05.10–31.12.2026: 459 активных экземпляров занятий, ноль совпадающих временных слотов после учёта периодичности и приоритета курсового часа.
- В PDF есть шум OCR и неоднозначные/искажённые даты (например, 32.11, 37.12, 39.12). Такие даты не активированы; несколько неоднозначных строк пропущены вместо догадок. Поэтому это ещё не подтверждение каждой строки PDF.
- Обязательная последняя проверка: дождаться успешного GitHub Pages deployment, затем проверить на телефоне все пять групп и контрольные даты. Не заявлять, что выполнена ручная проверка UI, пока пользователь её не подтвердил.

## Технический аудит — 23.10.2026

Проверено непосредственно в репозитории, Render и Supabase.

### Проверено
- В Supabase 17 групп и 566 записей расписания.
- В записях нет пустых предметов, пустых значений преподавателя/аудитории, некорректных временных диапазонов, регулярных записей без дня или разовых записей без даты.
- Проверка точных дублей по группе, типу записи, дню/неделе/дате, времени и предмету не нашла дублей.
- Генерация занятий с 05.10 по 31.12.2026 с учётом недель А/Б, исключённых дат, разовых замен и приоритета курсового часа не выявила пересекающихся пар. Это техническая проверка БД, а не независимая сверка каждой строки с PDF.
- Доступ к таблицам расписания через Supabase: публичное чтение; изменение расписания, ролей и журнала изменений политиками для anon/authenticated запрещено.
- Render API развернут и находится в статусе live. В репозитории есть workflow smoke-тестов API, проверяющий все четыре выгрузки, 17 групп, недели А/Б и разовые замены.
- Выполнена статическая проверка текущих файлов из GitHub: синтаксис встроенного JS, backend и четырёх адаптеров разбирается без ошибок; четыре расписания JSON корректно разбираются; дублирующихся DOM ID и отсутствующих ID-ссылок панели владельца не найдено. Добавлен `.github/workflows/frontend-audit.yml` для повторения этих проверок при изменениях интерфейса. Результат первого запуска GitHub Actions ещё не подтверждён через доступный инструмент.

### Важные ограничения, обнаруженные в коде
- На момент первоначального аудита Mini App загружала курс 2 через API, а курсы 1, 3 и 4 — из локальных JSON. Это состояние исправлено в разделе «Подключение всех курсов к API — 23.10.2026» ниже.
- В данных остаются аудитории «Уточняется накануне»: это не пустые поля и не ошибка формата, а неподтверждённые помещения из источников. Их нельзя заменять догадками. В сумме по текущей БД таких записей 141.
- Supabase Security Advisor отмечает две RPC-функции аналитики `SECURITY DEFINER`, доступные роли `anon`. Сейчас они проверяют секрет, который хранится на сервере Render, а таблицы аналитики находятся в закрытой схеме без клиентских политик. Это намеренное, но требующее дальнейшего укрепления место; не выдавать секрет в браузер и не добавлять через него функции изменения расписания.
- Текущая панель владельца предоставляет локальные визуальные настройки и диагностику; полноценное серверное редактирование расписания, роли старост и журнал правок ещё не подключены.
- Проверка по PDF не считается завершённой только на основании SQL/автоматических проверок. Все спорные даты, аудитории и OCR-неоднозначности требуют подтверждения по официальному источнику.

### Следующие технические действия
1. Проверить результат GitHub Actions после последнего обновления и доступность всех четырёх API-выгрузок.
2. Отдельно укрепить RPC аналитики и только после этого проектировать серверное редактирование расписания.
3. После сравнения с официальными PDF закрывать аудитории и спорные даты только подтверждёнными значениями.
